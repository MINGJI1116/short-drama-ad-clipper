# 海外短剧投流素材剪辑工作流（拼接 + 解说双轨 SOP）

> 适用范围：SODA TV 类海外短剧（英语/小语种）投流素材制作，覆盖「原片拼接」与「二创解说」两类素材。
> 本流程由 2026-11-13《假离婚真后悔》(TK) 实战项目复盘提炼，全部步骤已经过验证。
> 配套规范：《投流素材培训（202606）》。

---

## 〇、流程总览

```
素材接收 → 勘察建档 → 规范确认 → 选段规划(全局去重) → 元素制作 → TTS 配音
    → ffmpeg 批量构建 → 五维质检 → 命名交付
```

核心原则（血泪教训总结）：

1. **选段全局唯一**：10 条素材共享一个素材池时，任何一段画面只允许出现在一条素材里；
2. **切点吸附镜头边界**：跳剪必须在镜头切换处下刀，严禁在镜头中间跳；
3. **解说逐句对位**：每句解说配一个专属选段，从它描述的场景起点开始播；
4. **音轨只留主角**：解说版只有「解说 + BGM」两个层次，原片对白要么去掉、要么压到 0.15 以下；
5. **先审计后编码**：选段表必须程序化审计通过后再开渲染，避免整批返工；
6. **单条时长约 2 分钟**：每条素材（正片 + 落版）目标 ≈117–125s；规划选段前先算素材总量是否够（2 分钟 × 条数），不够就缩短条数或放开段长，不要交付 40–60s 的短条；
7. **解说密度必须够**：解说条句间停顿压到 1.5–2s，每 4–5 秒至少一句解说；成片交付前用 silencedetect 验证**不得存在 ≥2.5s 的无声段**（-30dB 阈值），BGM 必须全程覆盖。

## 一、Stage 1 素材接收与勘察（约 30 分钟）

### 1.1 目录盘点
拿到素材后先列全目录，确认五件套是否齐全：

| 素材 | 用途 | 本项目实例 |
| --- | --- | --- |
| 成片（带硬字幕） | 原片拼接的唯一画面来源 | 18 集，1080×1920 H.264 |
| 无字幕成片 | 解说素材的画面来源 | 与成片时间轴完全一致 |
| 人声/对白干声 | 解说素材氛围底（可选） | 第 N 集.mp3 对应第 N 集 |
| BGM/音效 | 解说素材垫乐 | 与集数一一对应 |
| 字幕 SRT | 选段定位 + 剧情分析 | 第 N 集.srt |

另需确认：品牌 logo（矢量或透明底 PNG 优先）、剧名（中文+英文）、剪辑师缩写。

### 1.2 规格勘察（ffprobe 逐条）
- 分辨率 / 编码 / fps / 时长 / 码率；
- **抽帧验证**（每集至少 3 帧：开头、中段、结尾）确认三件事：
  1. 是否自带烧录硬字幕（决定解说素材用哪套成片）；
  2. 是否已有 logo/贴片（决定要不要自己做界面元素）；
  3. 画面类型（真人/AI/动漫，影响封面与字幕样式选择）。

### 1.3 字幕 → Cue 表 → 剧情地图
把 SRT 解析成「序号 [入点-出点] 台词」的 cue 表，然后通读并标注：

- 剧情弧线：开端 → 虐点累计 → 爆点 → 复仇爽点；
- **付费卡点位置**（素材钩子必须卡在这里前一秒）；
- 名场面清单（对峙、反转、哭戏、打脸……按情绪强度排序）。

> 工具要点：SRT 时间轴是 `00:00:05,360` 逗号毫秒格式，解析时要先把 `,` 换成 `.`。

## 三、Stage 3 选段规划（本工作流的核心环节）

### 3.1 类型模板（按培训文档五类各出至少一条）

| 类型 | 结构 | 选段特征 |
| --- | --- | --- |
| 多集串联拼接 | A集悬念 → B集发展 → 钩子 | 每集 1–2 段，段间 2–8s |
| 单个高潮 | 一场完整高潮戏压缩 | 集中在同一集连续节点 |
| 高光混剪 | 名场面集锦，每段一句台词 | 段最短（1.5–4s），节奏最快 |
| 高光前置拼接 | 最炸画面放第 1 段 → 倒叙 | 第 1 段必须自带冲击力 |
| 二创解说 | 解说(抓手) + 原片(身子) + 钩子 | 见 3.3 |

### 3.2 镜头边界检测（跳剪质量的关键）
用 ffmpeg 场景切换检测拿到每集全部切点：

```
ffmpeg -i 第NN集.mp4 -vf "select='gt(scene,0.30)',showinfo" -f null - 2>&1 \
  | grep -o "pts_time:[0-9.]*" | cut -d: -f2 > epNN.txt
```

- 阈值 0.30 适用于真人剧；AI 剧切换较柔可降到 0.15；
- 输出解析认准 `pts_time:` 前缀（showinfo 的行格式为 `n: ... pts_time:123.456 pos:...`）；
- 选段入出点一律吸附到最近的切点，杜绝「跳在镜头中间」的顿挫感。

### 3.3 全局去重审计（编码前强制执行）
写一个审计脚本：把 10 条素材的全部选段汇成一个列表，两两检测（同集 + 时间区间重叠），输出重叠对。**审计不通过（0 重叠）不准开渲染。**

本项目数据：7 条拼接共 106 段 + 3 条解说共 32 段 = 138 段，0 重叠。
《Pregnant by My Husband's Friend》2 分钟版：7 拼接 + 3 解说共 238 段、1178.3s 独特画面（24 集总素材利用率 74%），0 重叠。

### 3.4 解说逐句对位
解说词按剧情写成单句（每句一个 tag），排程规则：

- 每句解说 → 一个专属选段，选段起点 = 该句描述的场景起点；
- 顺序游标排程：`下一句起点 = max(上一句结束 + 0.3s, 本选段起点 + 0.3s)`，**永不重叠**；
- **密度硬指标**：每段画面 = 语音时长 + 1.5–2s 停顿，不许钉在长镜头上干等；约 2 分钟的解说条要 26–30 句，插句优先填句间大空档（同集就近找空位，放不下顺延到下一空档二次扫描）；CTA 句强制置尾；
- 多条解说共享素材池时**联合分配**：先把各条原始段预登记进同一张占用表，再按条顺序圈地插句，否则条与条之间会互相撞段（全局审计会拦下）；
- 结尾 CTA 句（引导下载/搜索）压在落版上播，但字幕在落版出现前截断，避免文字打架。

### 3.5 解说词写作模板（英语三段式）
- 0–6s 抓手：身份反差 + 悬念钩子（"She was pregnant when she found out..."）；
- 身子：按「虐点 → 爆点 → 爽点」推进，每 20–30s 一个情绪峰值；
- 钩子/CTA：卡在付费卡点，收尾一句引导（"Watch the ending on SODA TV"）。

## 四、Stage 4 界面元素与配音制作

### 4.1 PIL 生成三件套（720×1280 基准）
1. **圆角 logo 贴片**：右上角（或左上角，避开主体），带轻微投影；
2. **片头剧名条**：品牌字样 + 英文剧名 + 装饰线，前 6 秒显示后淡出；
3. **落版片尾**（约 3s 静态图）：大 logo + 搜索框 + App Store / Google Play 按钮 + 引导语（"Watch the FULL drama for FREE"）+ 底部剧名。
   - **必须是不透明深色底**（半透明会透出底层画面）；
   - **必须是静态图**：动态按钮/指针点击效果有拒审风险。

### 4.2 Edge 神经语音配音（edge-tts）
- 声线：`en-US-AvaNeural`（女，解说感强）/ `en-US-AndrewNeural`（男）；语速 `+8%`；
- 逐句生成 mp3，同时记录每句时长到 durations.json（排程要用）；
- 避坑：Windows SAPI（Zira 等）机器感重、吐字含混，**不要用于成片**；多句配音严禁用固定偏移排程（前后句会叠上）。

## 五、Stage 5 ffmpeg 批量构建

### 5.1 视频链（每条素材）
```
选段 trim → scale=720:1280 → overlay(logo 全程 + 剧名条前6s) →
fade in/out → [解说条: subtitles=ASS字幕] → concat(正片) → concat(落版3s) →
libx264 CRF19 + AAC 160k
```

### 5.2 音频链
- 拼接条：选段原声直通（音画同步是底线）；
- 解说条：`解说 ×1.35（adelay 按排程入）` + `BGM ×0.13–0.16（afade in/out）`，两轨 amix；
- **BGM 时长必须 ≥ 成片时长**：构建链用 `atrim=0:总长` 截断垫乐，BGM 偏短则片尾整段裸奔无声（实测 80s BGM 配 120s 片，后 40s 零声音）。合成/下载 BGM 时直接按目标时长 +10s 余量做；
- 原片对白处理：解说条**直接不用**人声干声（实测三层人声必糊）；若确需氛围底，压到 0.15 以下。

### 5.3 环境与版本坑（实测记录）
- 本工作流用 **ffmpeg 9.0.2**（`imageio_ffmpeg.get_ffmpeg_exe()` 自带，免下载）；
- ffmpeg 9 **移除了 `-filter_complex_script`**，长滤镜图改用 `-/filter_complex 文件路径` 或直接内联；
- 滤镜需求清单（构建前逐个验证）：libx264 / drawtext / subtitles(ass) / delogo / xfade / loudnorm / amix / adelay / volumedetect；
- 字幕烧录用 ASS：样式 `Arial 40号 白字 黑边(Outline=3) MarginV≈380`（= 底部三分之一上沿），每行 ≤28 字符，最多 3 行，否则出画面边。

### 5.4 码率达标技巧
- CRF 20 实测 ≈2400kbps（不达标）→ CRF 19 ≈2600–3000 → **默认 CRF 19**；
- 个别画面简单、码率仍 <2500 的单条，用 CRF 18 单独重编码；
- 严禁压码率到 2500 以下，宁可 CRF 降一档。

## 六、Stage 6 五维质检（全部 PASS 才算完成）

| 维度 | 工具 | 达标线 |
| --- | --- | --- |
| 规格 | ffprobe | 720×1280 / H.264 / 30fps / 码率≥2500kbps / AAC |
| 电平 | volumedetect | 峰值 -1.5 ~ -3dB，解说条无削波 |
| 静音 | silencedetect(noise=-30dB:d=2.5) | **≥2.5s 无声段数量 = 0**（解说条尤其必查） |
| 音频内容 | AI 转录（AudioTranscribe） | 解说逐句清晰、顺序正确、无糊音无重叠；同路径重复转录疑似缓存，用改名切片转录复验 |
| 画面 | 定点抽帧（1s/中段/结尾） | 字幕在框内不超边、logo/剧名/落版完整无重叠 |
| 命名 | 人工对照九段式 | 时间_序号_剧名_代号_集数_分类_时长_缩写_自定义 |

抽帧五个必查点：① 解说字幕宽度与位置；② logo 贴片；③ 片头剧名条；④ 落版各元素；⑤ 结尾衔接（正片自带渐黑 + 落版观感是否自然）。

## 七、Stage 7 命名与交付

- 九段式：`YYYYMMDD_序号_中文剧名_剧代号_集数_素材分类_素材时长_缩写_自定义项`；
- 集数：连续用 `--`（1--4），不连续用 `-`（1-4-8），单集写 `7-7`；
- 素材时长按分钟向下取整写 `1`；跳剪写自定义项，混剪写素材分类（二选一，不重复写）；
- 单文件 >500M：压素材本身（保持 720p、比特率 2500+），不压打包文件；
- 随批附《交付清单.md》：每条的集数来源、类型、钩子卡点、码率时长速查表 + 待确认事项。

## 八、踩坑记录（本项目实际发生的问题与对策）

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 1 | 解说音频糊成一片 | 解说+原片对白+BGM 三层人声打架 | 解说条去掉对白轨，只留解说+BGM |
| 2 | 解说前后句互相压上 | 固定偏移排程，间隔 < 句长 | 顺序游标排程，程序验证 0 重叠 |
| 3 | TTS 吐字含混错读 | Windows SAPI 语音质量差 | 换 edge-tts 神经语音 |
| 4 | 多条素材画面大量重复 | 选段表未做全局查重，长段共用 | 镜头检测 + 全局唯一审计 + 短选段化 |
| 5 | 跳剪有长连续镜头 | 最长一段 33s 连续画面 | 全部拆成 2–8s 短段 |
| 6 | 解说字幕超出画面 | 字号 46 + 每行 44 字符 | 40 号 + 每行 28 字符 |
| 7 | 落版与结尾字幕重叠 | outro 字幕压在落版元素上 | 字幕在落版前截断 |
| 8 | 视频码率不达标 | CRF 20 偏高 | 默认 CRF 19，个别 18 |
| 9 | ffmpeg 9 报未知选项 | `-filter_complex_script` 已移除 | 改 `-/filter_complex` |
| 10 | 场景检测提取不到切点 | showinfo 行格式解析错误 | 认准 `pts_time:` 前缀提取 |
| 11 | 解说片中段起十几秒纯无声 | BGM 比片子短被 atrim 截断 + 句间停顿 6–10s | BGM ≥ 片长+10s；停顿压 1.5–2s、加插句；交付前 silencedetect 复验 |
| 12 | 解说个别句子重复播放 / 张冠李戴 | 重配 TTS 后 durations.json 的 file 映射被旧状态污染，排程按行号取到错音频 | 每次重配 TTS 后立即校验 file 映射唯一且有序；排程按**文本**匹配音频而非行号；终排脚本只跑一次，防自我污染循环 |
| 13 | 多条解说素材互相撞段（全局审计拦截） | 插句时占用表只算拼接条，没算其它解说条 | 三条解说联合分配：共享占用表 + 原始段预登记 + 按顺序圈地 |
| 14 | 转录复核结果与旧版一模一样 | AudioTranscribe 对同路径文件疑似有缓存 | 用新文件名的 10–12s 切片转录复验，与时刻表逐句比对 |
| 15 | 片头剧名条文字超宽出画 | 固定 84pt 字号遇长英文剧名 | 剧名条字号按画面宽度自适应（max 宽 660px 内逐级缩字号） |

## 十、单条素材工时参考（熟练后）

勘察建档 0.5h → 选段规划 1h → 元素制作 0.5h（一次制作全批复用）→ 配音 5min → 构建 2min/条 → 质检 10min/批 → 命名交付 15min。
**10 条素材全程约 2.5–3 小时**（含审计与返工缓冲）。
