# 首次场景案例库（pitfalls.md）

> 记录 skill 首版未覆盖、实战中首次踩到的场景。每例含：现象 → 根因 → 解决 → 通用规则。
> 新项目开工前通读一遍；遇到本文件未覆盖的新场景，修复后**按同样四段式追加**进本文件，并同步 GitHub 镜像仓库。
> 首例全部来自 2026-11-15《在撤侨航班上同学说我们都是假护照》(OAEN2803, 30 集) 项目。

## 案例 1：分集文件名不规则（特殊后缀 + 两目录写法不一致）

- **现象**：survey 阶段发现第 4 集叫 `第04集(卡点集）.mp4`（半角前括号+全角后括号）、第 5 集叫 `第05集（付费集）.mp4`；且"成片"与"无字幕文件"两个目录对同一集的后缀写法不一致，单一 `episode_pattern` 无法匹配全目录。
- **根因**：平台方导出时对卡点/付费集追加了后缀，且两个目录由不同批次导出。
- **解决**：不动原始文件，用 **NTFS 硬链接**建规范化媒体目录，全部统一为 `第NN集.mp4` 后再进流水线：
  ```bash
  W="<work>/media"; mkdir -p "$W/cheng" "$W/nosub"
  cmd //c mklink //h "$(cygpath -w "$W/cheng/第NN集.mp4")" "$(cygpath -w "<原始路径>")"
  ```
  project.json 的 `episode_pattern` 指向规范化目录，源路径字段仍填硬链接（同一份数据，零拷贝）。
- **通用规则**：**survey 后、scene_cuts 前**，逐集核对文件名能否被单一 pattern 覆盖；不能 → 先建硬链接规范化目录。严禁用 `cp` 复制几十 GB 原片，严禁重命名用户原始文件。

## 案例 2：贴片/落版中文字体缺字（渲染成方框）

- **现象**：gen_assets.py 用 `segoeuib.ttf` 渲染中文剧名，产出 PNG 里中文全是方框。
- **根因**：Segoe UI 无 CJK 字形。
- **解决**：外语剧直接改用**原文剧名**做贴片（本剧用英文剧名）；中文剧把字体换成 `C:/Windows/Fonts/msyh.ttc`（微软雅黑）。
- **通用规则**：**任何贴片/落版生成后必须 ViewImage 验字**，不能只看脚本 exit 0。字体选择跟随剧名语种：拉丁→segoeuib，中文→msyh，其他语种先验字再批量。

## 案例 3：落版底部剧名超宽被裁切

- **现象**：剧名较长时，end_card.png 底部剧名超出 720px 画宽被裁掉。
- **根因**：固定 30px 字号 + 居中排版，未做宽度自适应。
- **解决**：gen_assets.py 已改为按 `textlength` 自适应缩字号（先按目标字号测宽，超宽则等比缩小，设下限 18px 防过小）。**此修复已进 skill 代码**。
- **通用规则**：所有固定画布上的动态文本，一律先测宽再排版，禁止假设"剧名不会太长"。

## 案例 4：暗场剧 CRF 编码欠码率

- **现象**：机舱夜戏占比高的剧，CRF 16 编出 ~2300kbps，低于 2500k 交付线；pipeline 自动降 CRF 重试 2 次仍不达标（CRF 已到底，降无可降）。
- **根因**：CRF 是质量恒定模式，低复杂度暗场画面本身码率就低；质量达标 ≠ 码率达标，而平台按码率卡交付。
- **解决**：build_clip.py 新增 **ABR 模式**：环境变量 `export VBR_TARGET=2800` 后，改用 `-b:v 2800k -minrate 0.85×2800k -maxrate 4000k` 强制码率下限。**此修复已进 skill 代码**。
- **通用规则**：pipeline 降 CRF 重试仍欠码率时，**不要继续降 CRF**（无意义），直接 `VBR_TARGET=2800` 全量重建欠码率的条目。暗场/夜戏占比高的剧建议 Stage 5 一开始就开 ABR。

## 案例 5：BGM 素材响度过低（混进去等于没混）

- **现象**：解说条交付后用户反馈"没有 BGM"。实际混了，但成片里 BGM 段仅约 -60dB。
- **根因**：**分集 BGM 素材本身只有 -38.6 LUFS**（导出时未做响度归一），再乘 0.14 混音增益后不可闻。
- **解决**（两步，已进 skill 代码）：
  1. **归一化**：`ffmpeg -i bgm.wav -af loudnorm=I=-20:TP=-2:LRA=7 bgm_norm.wav`，开工时先 `ebur128` 测素材响度；
  2. **闪避混音**：build_clip.py 新增 `bgm_duck` 模式（project.json 设 `"bgm_duck": true, "bgm_gain": 0.6`）——解说 amix 后 `asplit` 出 sidechain，`sidechaincompress=threshold=0.03:ratio=10:attack=15:release=350` 对 BGM 闪避：说话时压低不抢人声，句间浮出补底，片尾淡出。
- **通用规则**：
  - BGM 素材**先测响度再进流水线**：`ffmpeg -i bgm.wav -af ebur128 -f null -`，Integrated < -30 LUFS 必须先 loudnorm；
  - 混完必须**逐窗验证句间 BGM 底**：目标比人声段低 9~12 LU（句间 RMS 约 -25~-33dB）。测量方法必须用 `astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level` 再统计——直接 `astats=reset=1` 只会在结尾打 Overall 汇总，得不到逐窗数据（本次实测踩坑）。

## 案例 6：edge-tts 瞬时 503

- **现象**：整批 TTS 中途报 503 Service Unavailable，部分句子缺文件。
- **根因**：微软 TTS 服务瞬时过载，非代码问题。
- **解决**：单句 probe 确认服务恢复后**整批重跑**（脚本会覆盖补齐）。
- **通用规则**：TTS 失败先 probe 再重跑，**不要因 503 改声线/语速/代码**；重跑后校验 durations.json 映射唯一且有序（sop.md 既有规则）。

## 案例 7：解说锚点排程重叠

- **现象**：解说条构建时同集段重叠，全局审计拒绝渲染。
- **根因**：排程用"期望起点"直接落位，未与前一句实际结束时间做单调约束；TTS 实际时长与预估不符时必然叠加。
- **解决**：锚点排程改单调游标：`actual_start = max(desired_start, prev_end + gap)`（gap ≈ 1.3s，同时满足停顿 ≤2s 密度要求）。
- **通用规则**：任何逐句时间轴排程，必须用游标法单调推进，禁止固定偏移（与 sop.md"顺序游标"规则同源，此处补充：TTS 实测时长回填后要重排而非只平移）。

## 案例 8：bgm_duck 模式片尾整段静音（sidechaincompress 截断）

- **现象**：解说条交付前 silencedetect 发现存片尾部有 3–5s 数字静音（-inf），位置固定在"最后一句解说说完"之后；换 BGM 增益（0.14→0.6）、做 loudnorm 归一均完全无效（静音区间逐位一致，证明是结构性截断而非电平问题）。
- **根因**：`bgm_duck` 路径里 `[nv]asplit=2[nsc][nmix]` 把解说混音直接喂给 `sidechaincompress` 作侧链。ffmpeg 的 sidechaincompress 在**侧链流 EOF 时终止输出**——解说最后一句播完，BGM 底被连同截断，`apad` 只能把已截断的信号补成静音。
- **解决**：asplit 后先给侧链补齐全片长再进闪避：`[nsc0]apad=whole_dur=<total+0.5>[nsc]`。**修复已进 skill 代码（build_clip.py）**。
- **通用规则**：排查"尾部静音"类问题时，先用 `astats RMS_level` 看是低电平（-30dB 左右，查素材响度/增益）还是 **-inf（数字静音，查滤镜图截断）**——两者修法完全不同；任何 sidechain 类滤镜，侧链时长必须显式补齐到主输入长度。另外 loudnorm 不会填补素材真静音，对"换增益/归一后静音逐位不变"的现象要立刻转向结构排查。

## 附：效率复盘结论（2026-11-15）

30 集项目耗时 ~2 小时（平时 0.5–1 小时），拆解：环境冷启动 ~40 分钟（本目录 environment.md 可全部避免）+ 首次场景现场修复 ~35 分钟（即本文件案例 1–7，修复均已沉淀进代码）+ 真实编码机器时间。选段/排程/质检的判断耗时与既往项目持平。**新项目按 environment.md 启动、开工前通读本文件，预期回到 30–60 分钟。**
